# 配额中枢 · astrbot_plugin_quota_hub

对 **个人私聊 / 整个群共享 / 群内每个成员** 三种作用域，按 **小时级滚动短窗口**
与 **天级锚定长窗口** 做 **调用次数** 与 **Token 额度** 双重限额，支持用户自助
重置与申请。内置 **数据中台** 可视化与动态调参，管理员可用指令实时调整配额。
无需 Redis、无需额外端口——纯用 AstrBot 原生「插件 Pages」+ SQLite（Python 内置）。

> ⚠️ 与 `astrbot_plugin_daily_limit` 功能冲突：二者都挂 `on_llm_request`，同时启用会造成双重限流，请勿同时启用。

## 安装

- **方式一（推荐）**：AstrBot WebUI → 插件市场，搜索 `astrbot_plugin_quota_hub` 安装。
- **方式二**：克隆到 AstrBot 的 `data/plugins/` 目录后在 WebUI 重载插件：

  ```bash
  cd AstrBot/data/plugins
  git clone https://github.com/Dracowyn/astrbot_plugin_quota_hub.git
  ```

仅依赖 Python 标准库与 AstrBot 自带依赖（quart），无需额外安装。要求 AstrBot `>=4.24.2`。

## 特性

- **三作用域同时生效**：群聊消息会 **同时** 检查「全群共享额度」与「群内成员个人额度」，任一超限即拦截。
- **双指标**：调用次数为硬限；Token 为软限（窗口内累计达上限即拦截下一条）。`-1` 表示该指标不限。
- **短窗口**：统计「最近 N 小时」（默认 5，可配）的**滚动**窗口，随时间平滑滚动、逐条恢复。可对单实体设置专属窗口。
- **长窗口**：以天计的**锚定**窗口（默认 7 天，`-1` 表示不限）。实体第一次放行调用时开窗，满 N 天整体到期归零，每个实体的开窗时刻各不相同；判定先长窗口后短窗口，长窗口耗尽**永远拦截**、不参与回退。
- **自助重置与申请**：管理员可开放 `/quota reset me [long]` 让用户自助重置自己短 / 长窗口的用量，每个实体、每种窗口各自有限量的「重置次数」（随长窗口周期自然到期补满）；次数不够时可 `/quota request` 向管理员申请追加，审批后自动通知申请者。重置只是记「重置标记」/ 结束当前周期，**不删除**用量记录，历史统计不受影响。
- **触顶自动使用重置次数**：配置项 `auto_reset_on_block`（默认关闭）。开启后，
  请求触顶被拦截时系统自动为你消耗一次**触发窗口**（短窗口触顶消耗短窗口次数、
  长窗口触顶消耗长窗口次数）的重置次数并重新判定，通过则本次请求继续；前置
  条件与 `/quota reset me` 完全一致（受限流约束、短窗口需有用量 / 长窗口需有
  进行中周期、次数 > 0），但**不受 `allow_self_reset` 控制**——两者是独立开关。
  群共享池**永不**自动重置（群池只有管理员可重置）；作用的实体与手动自助重置
  一致：群里为「你在本群」的成员实体、私聊为私聊实体。`self_reset_long_count`
  默认 `0`，故长窗口自动重置默认不会发生。每次请求最多自动重置一次（不连锁），
  且**不会白扣次数**：落盘重置前会先做一次干跑判定「重置之后还会不会被拦」，
  若长短窗口同时超限、或群共享池已满等情况下重置也救不回来，就直接照常拦截、
  不消耗次数；仅在极少数并发场景下（重置落盘期间被别的请求抢先用满额度）才
  可能出现「已消耗次数但仍被拦截」，此时会先提示次数已消耗、再发送常规拦截
  提示。长窗口自动重置会结束当前周期，下一个周期**不补满**次数（与手动长
  重置同规则）。默认在会话内提示一次，模板 `auto_reset_message`（默认
  `♻️ 已达{window_label}上限，自动为你使用 1 次重置（本周期剩余 {remaining}
  次），本次请求继续。`），可用变量与拦截提示同一套外加 `{remaining}`（重置后
  该窗口的剩余次数）：`{scope} {scope_label} {window_label} {window_days}
  {metric} {metric_label} {used} {limit} {window_hours} {reset_in}
  {remaining}`；`auto_reset_silent`（默认关闭）开启后不提示，用户仍可从
  `/quota me` 的剩余次数与中台「重置日志」（「发起」列显示「自动」）看到。
  若「超限时的措施」为 `fallback`，自动重置把拦截翻成回退判定时供应商预选
  时机已过，**本次请求仍走主模型**、不会发送「已切换到备用模型」提示，下一
  次请求的预选钩子才会正常切换。自动重置内部发生异常时降级为照常拦截并记
  一条 warning 日志，**不会放行**。
- **逐实体覆盖**：可对具体某个人 / 某个群 / 某群内某人设置专属配额，覆盖默认值；还可对某群设置**群内成员默认配额**（对该群全体成员生效）、对某用户设置**用户级成员默认配额**（该用户在所有群生效）。成员生效配额的解析链（后者优先）：全局默认 → 群成员默认 → 用户级成员默认 → 具体成员专属覆盖，逐字段继承（短窗口、长窗口、重置次数、回退均可分别覆盖）。
- **两种生效范围**：`allowlist`（默认，仅监控列表内生效）或 `all`（全员生效，白名单豁免）。
- **超限回退备用模型**：「超限时的措施」选 `fallback` 后，达到常规上限不再拦截，而是在「常规上限 + 回退额度」的硬上限内改用备用模型继续回复，超过硬上限才拦截；备用模型与回退额度（调用 / Token 分别设置）可逐实体覆盖，切换时可在会话内提示一次。回退只对短窗口生效，长窗口不参与。
- **数据中台**：默认展示按群 / 按人用量、趋势图；按群 / 按人 / 成员表均含长窗口列（调用、Token、到期时间）与剩余自助重置次数（按人 / 成员，「短 N · 长 M」，有待审批申请时附「申请中」徽标），可在页面上直接编辑配额（含长窗口与自助重置次数字段）、重置用量（短 / 长窗口二选一）、发放重置次数；「申请与重置」TAB 集中处理重置次数申请的批准 / 拒绝与重置日志；顶部 TAB 可切到配置页。
- **历史统计**：明细定期清理之外，另有小时级汇总**长期保留**（`history_retention_days`，默认永久、开销极小）。「历史统计」页提供 24 小时 / 7 / 30 / 90 / 365 天的用量趋势（24 小时按整点、多日按自然日）、群 / 用户排行、模型 / 平台分布与 7×24 时段热力；`/quota stats [天数]` 可在会话内查看文字版。
- **高并发友好**：限流判定走 **内存滚动窗口聚合器**（零数据库访问），用量 **异步批量** 落盘到 SQLite，瓶颈始终是 LLM 而非数据库。

## 指令

### 普通用户可用

```
/quota me                                      查询自己的用量、剩余重置次数与申请状态
/quota help                                    指令帮助
/quota reset me [long]                         自助重置自己的短 / 长窗口用量（消耗一次重置次数）
/quota request short|long [数量=1] [理由]      申请追加重置次数，等待管理员审批
```
`/quota me` 受配置项 `allow_user_query` 控制（管理员不受限，关闭后普通用户收到
`query_denied_message` 提示）；每个作用域展示短窗口一行（含约 X 后开始恢复）、
长窗口一行（含到期时间，或「当前无进行中的周期」），末尾一行显示剩余自助重置
次数、待审批申请与尚未送达的审批结果。
`/quota reset me` 受 `allow_self_reset` 控制；群共享池不能自助重置——群里
`/quota reset me` 作用于「你在本群」的成员实体，私聊则作用于私聊实体。
`/quota request` 需要该实体当前有进行中的长窗口周期，且同一实体同时只能有
一条待审批申请，数量不超过 `request_max_count`（默认 3）。

### 管理员指令

```
/quota set user|group|member <...> <次数> <Token> [小时]
/quota set members <群号> <次数> <Token> [小时]     某群全体成员的默认配额
/quota set userdef <用户ID> <次数> <Token> [小时]   该用户在所有群的成员默认配额
/quota setlong user|group|member|members|userdef <...> <次数> <Token> [天数]
                                                    只写长窗口三个字段
/quota setreset user|member|members|userdef <...> <短窗次数> <长窗次数>
                                                    只写「每周期自助重置次数」两个字段
/quota clear   user|group|member|members|userdef <...>   删除覆盖（回落默认）
/quota reset   user|group|member <...> [long]      重置某实体的短 / 长窗口用量（不消耗次数）
/quota grant   user <用户ID> <短窗次数> <长窗次数>  为私聊实体发放重置次数（加到当前周期）
/quota grant   member <群号> <用户ID> <短窗次数> <长窗次数>
/quota requests                                    列出待审批申请（顺带作废已过期的）
/quota approve <id> [数量]                         批准申请（数量默认为申请数量）
/quota deny    <id> [理由]                         拒绝申请
/quota session                                     打印当前会话标识，用于填入「申请通知会话列表」
/quota monitor add|del group|user <ID>             维护监控名单（allowlist 模式）
/quota exempt  add|del group|user <ID>             维护白名单（all 模式）
/quota stats [天数]                                用量概览；带天数（1-365）时查看历史统计
```
次数 / Token 填 `-1` 表示不限；小时 / 天数省略则沿用当前设置或全局默认窗口。
对已有覆盖的实体，`/quota set`（及 `setlong` / `setreset`）只更新显式给出的
字段，其余覆盖字段（含回退设置、停用状态）保持不变。

**重置的行为**：`/quota reset`（指令或中台）只是给实体记一条「重置标记」时间戳
（短窗口）或结束当前周期（长窗口），**不会删除底层用量记录**，历史统计不受
影响；`reset member` 不再连带扣减群共享池用量（该旧行为已在 0.4.0 移除，
见 [ADR 0001](./docs/adr/0001-reset-marker-instead-of-deleting-events.md)）。
管理员重置不消耗自助重置次数。

**发放 / 申请注意事项**：`/quota grant` 与 `/quota approve` 都要求该实体当前
有进行中的长窗口周期，否则会提示「当前没有进行中的周期」——发放只加到当前
周期，长窗口自然到期时会被「补满至配置值」抹掉，不会累积。
申请审批结果会尝试主动推送给申请者，推送失败（例如 `qq_official` 平台不支持
主动推送，或对方从未与机器人主动对话过）则在其下次 `/quota me` 时展示一次。

## 数据中台

WebUI → 插件列表 → 进入「配额中枢」插件详情 → 打开「配额中枢」Page：

- **数据中台**（默认）：概览卡片、用量趋势图；按群表（短 / 长窗口调用与 Token、
  长窗口到期时间）与按人表（私聊与长窗口用量、到期、剩余自助重置次数、「申请中」
  徽标）；每行可「编辑配额 / 重置 / 查看成员」，按人表另有「发放」。
  - **配额弹窗**：除次数 / Token / 窗口小时外，新增「长窗口」分隔（长窗口调用 /
    Token 上限、长窗口天数）与「自助重置次数」分隔（短 / 长窗口次数，留空继承
    默认；群作用域不展示该分隔，群共享池不支持自助重置）。
  - **重置弹窗**：可选「短窗口」（清空当前短窗口用量、写重置标记）或「长窗口」
    （结束当前周期，重置次数不补满）。
  - **发放弹窗**：为私聊 / 成员实体直接追加短 / 长窗口自助重置次数，不经过申请
    流程。
  - **成员弹窗**：成员表新增长窗口列（调用 / Token 合并展示）、到期列、剩余重置
    列，操作含「配额 / 发放 / 重置」。
- **申请与重置**：「重置申请」表可切换「待审批 / 全部」，对待审批申请「批准」
  （可改发放数量）或「拒绝」（可填理由）；「重置日志」展示最近 100 条重置记录
  （含指令、自助、自动与中台操作），「发起」列取值「本人 / 管理员 / 自动 / …」，
  触顶自动使用重置次数记为「自动」。
- **历史统计**：24 小时 / 7 / 30 / 90 / 365 天时间范围切换；用量趋势（24 小时视图按整点、多日视图按自然日，Token / 调用指标切换）、群 / 用户排行、模型 / 平台分布、周几 × 小时的时段热力。数据来自小时级汇总 + 未固化明细的合并口径，统计到当前时刻。
- **配置**：从 schema 渲染表单，编辑后保存即生效（含监控 / 白名单、默认配额、窗口、拦截文案等，长窗口与重置次数的默认值也在此配置）。

## 统计口径说明

- **调用在请求发出前计次**：LLM 调用失败不退还额度（避免失败重试绕过限流）；
  响应未回传 usage 时该次 Token 记 0。
- **多轮工具调用的 Token 以最后一轮响应的 usage 计**（AstrBot 暂未向插件钩子暴露
  全程累计值），实际消耗可能略高于统计值。
- **`/quota reset`（指令或中台）不删除底层用量记录**：短窗口重置写入一条「重置
  标记」时间戳，该窗口只统计标记之后的用量；长窗口重置直接结束当前周期。用量
  事件本身永不因重置而删除，**历史统计完全不受影响**——历史即历史。中台「当前
  用量」按标记后口径展示；「按人」合计只扣减私聊实体标记前的那一段用量。
- **长窗口用量从明细重算**：只持久化开窗时刻与重置标记，累计的调用 / Token 数
  在启动时从 `usage_events` 重新汇总，而非把计数器当权威数据落库（详见
  [ADR 0002](./docs/adr/0002-anchored-long-window-rebuilt-from-events.md)）。
- **明细保留期护栏**：`retention_days` 小于当前最长的长窗口天数时，实际清理会
  以长窗口天数为准（否则长窗口用量在到期前就重算不出来了）。
- **保留期同时清理重置审计日志**：`retention_days` 除清理用量明细外，也用来
  清理重置审计日志 `reset_log`（自助 / 自动 / 管理员重置的记录），
  `retention_days <= 0` 时不清理；超出保留期的记录会被定期清理，中台「重置
  日志」只能看到保留期内的记录（`reset_log` 不参与任何限流判定，纯用于展示
  与审计，清理不影响额度本身）。

## 架构

```
main.py            插件入口：on_llm_request 拦截 / on_llm_response 回填 / 指令 / 注册 Web API
core/aggregator.py 内存滚动窗口聚合器（热路径，零 DB，短窗口滑动 + 长窗口锚定计数）
core/writer.py     异步批量落盘队列
core/storage.py    SQLite(WAL + busy_timeout，单写连接 + 锁 + to_thread)
core/storage_history.py 小时级汇总固化（usage_hourly）与历史统计查询
core/storage_state.py   周期状态 / 重置日志 / 重置次数申请三张表的存储层
core/quota.py      配额解析（覆盖优先）/ 拦截判定 / 文案
core/windows.py    滚动窗口时间计算
core/cycles.py     长窗口周期、重置标记与重置次数的纯状态机
core/requests.py   重置次数申请（ResetRequest）状态机
core/models.py     不可变模型与作用域工具
services/cycle_service.py  周期服务：状态转移落到「内存缓存 + 落盘 + 聚合器同步」三处并保证一致
services/request_service.py 重置次数申请服务：审批 / 拒绝 / 发放的核心逻辑，指令与中台 API 共用
api/routes.py      数据中台 Web API（Mixin）
api/serializers.py 中台 API 的字段解析与响应序列化（quota / override / cycle / request / log entry）
pages/dashboard/   前端（index.html / app.js / style.css）
```

数据存储于 `data/plugin_data/astrbot_plugin_quota_hub/quota.db`。
